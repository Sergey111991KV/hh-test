# Контур — мини-CRM «Объекты и задачи»

Мини-CRM для строительной команды: руководитель ведёт объекты и ставит задачи, исполнители работают только со своими назначениями, а каждое изменение статуса остаётся в истории.

## Стек

- React + TypeScript + Vite
- Supabase Auth и PostgreSQL
- RLS-политики для объектов, задач и истории
- SQL-функции для создания и изменения задач

## Возможности

- Вход по почте и паролю без открытой регистрации.
- Руководитель создаёт, меняет и убирает из активного списка объекты и задачи, назначает исполнителей, принимает задачи и возвращает их на доработку.
- Исполнитель видит только свои задачи и связанные с ними объекты, берёт задачу в работу, отправляет её на проверку и продолжает после возврата.
- Карточка задачи показывает описание, исполнителя, объект, доступные действия и хронологию переходов статуса.
- Удаление объектов и задач выполняется мягко: записи исчезают из активного списка, история остаётся сохранной.

## Локальный запуск

Нужны Node.js 20.19 или новее и pnpm.

1. Установите зависимости командой **pnpm install**.
2. Скопируйте **.env.example** в **.env.local**.
3. Заполните **VITE_SUPABASE_URL** и **VITE_SUPABASE_PUBLISHABLE_KEY** значениями из панели Supabase → Connect.
4. Примените миграцию и демо-данные, как описано ниже.
5. Запустите **pnpm dev** и откройте адрес, показанный Vite.

Production-сборка: **pnpm build**. Папка для размещения — **dist/**.

## Настройка Supabase

Создайте проект Supabase и примените файл **supabase/migrations/202611060001_initial_schema.sql** через SQL Editor или Supabase CLI. Миграция создаёт профили, объекты, задачи, историю, политики доступа и RPC-функции.

В Supabase Auth отключите публичную регистрацию и вручную создайте три подтверждённые тестовые учётные записи:

- **manager@example.com** — руководитель;
- **executor1@example.com** — исполнитель;
- **executor2@example.com** — исполнитель.

Задайте пароли при создании учётных записей. Не записывайте их в репозиторий. После создания выполните **supabase/seed/demo.sql**. Скрипт назначит роли и имена и добавит три объекта и шесть задач в разных статусах. Его безопасно запускать повторно.

Роль каждой новой учётной записи по умолчанию — исполнитель. Роль руководителя меняется только администратором базы данных, не из браузера. Не помещайте **service_role key** или пароль базы данных во фронтенд, **.env.example** или репозиторий. В Vite можно передавать только URL проекта и publishable/anon key: права на строки ограничивают RLS.

## Данные и безопасность

Все таблицы приложения закрыты RLS. Исполнитель получает строки назначенных ему задач и объектов, в которых у него есть задачи; руководитель видит рабочие данные команды. Создание, редактирование и мягкое удаление задач, а также смена статуса выполняются проверяемыми SQL-функциями. База повторно проверяет роль, назначение и разрешённый переход статуса, поэтому скрытие кнопки в интерфейсе не является единственным барьером.

Статусы и допустимые переходы:

| Сейчас | Дальше | Кто |
| --- | --- | --- |
| Новая | В работе | Назначенный исполнитель |
| В работе | На проверке | Назначенный исполнитель |
| На проверке | Принята | Руководитель |
| На проверке | На доработке | Руководитель, с комментарием |
| На доработке | В работе | Назначенный исполнитель |

История записывается триггером базы и не имеет API-прав на изменение или удаление. Открытая регистрация выключена; профили новых Auth-пользователей создаются триггером с ролью исполнителя.

## Развёртывание

Приложение рассчитано на Vercel или Netlify. Подключите репозиторий, задайте переменные окружения **VITE_SUPABASE_URL** и **VITE_SUPABASE_PUBLISHABLE_KEY**, затем используйте команду сборки **pnpm build** и каталог **dist**. Для SPA-навигации добавлены **vercel.json** и **netlify.toml**.

Рабочая публичная демо-ссылка требует активного проекта Supabase и аккаунта/прав на хостинг. Демо-пароли и секретные ключи в репозиторий не добавляются.
